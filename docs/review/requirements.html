1. 产品目标与读者

构建中文 HTML 交互学习材料，让读者点击一次请求的执行步骤，从业务、应用、模型和基础设施理解 LLM inference。先回答“发生什么、为什么、对体验有什么影响”，再展开术语、配置、公式与方案细节。

目标读者是 Cisco 客户、合作伙伴、销售和售前工程师，日常背景为网络维护、虚拟化维护和云平台维护，没有 AI 基础。详细前置知识、类比边界和角色路线见目标读者规范。不要求编程、机器学习或 GPU 经验，不按职位推定技术深度。

提供“理解与沟通”和“方案与工程细节”两层阅读。职业角色入口推荐学习路线；user/agent/model/infra 四个运行视角观察同一个流程，两者不得混为一谈。

学习完成后，读者能解释 Agent、模型、工具和 RAG 的职责；把响应体验关联到 token、队列、计算、缓存和通信；收集容量规划输入；辨认 UCS/GPU 支持证据、显存估算和实测性能的不同作用；用逐层定位方法分析运维问题。

4. 用户旅程与交互边界

  1. 选择沟通或方案路线，从酒店请求认识参与者。
  2. 点击下一步，逐项查看输入、执行者、输出和状态；基础说明不依赖代码或公式。
  3. 在澄清、库存、候选、确认和提交节点观察 Agent 与工具的责任；尝试无房、超时、价格变化分支。
  4. 保留当前步骤切换运行视角，追踪模型调用的 prefill/decode 和单卡队列；展开术语与配置细节。
  5. 用知识库案例理解 RAG，再用模型配置、GPU 对照与每卡账本规划资源。
  6. 改变长度、到达率、并发或部署方式，解释体验变化；进入变慢、争用、节点故障案例并选择排查路径。
  7. 完成简短自测，得到“还应收集哪些信息、如何验证方案”的清单。

酒店持续标注“模拟”；用户明确确认之前不可进入模拟提交，结果只能写“模拟预订完成”。知识库、指标、资源与网络动画也标明教学数据。指标不得把字符当 token，不能把整段 Agent 的工具等待归入 GPU 计算时间。
