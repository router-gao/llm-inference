## 决策与责任

- 产品方向：用户给定方向优先；普通实现选择由负责人在范围内决定，记录重要取舍。
- 技术事实：对应内容负责人提供来源与适用范围，QA核对；前端不自行编造缺失行为或参数。
- 交互契约：experience维护，inference/infra提供结构化步骤与数值假设。
- 状态与排期：项目负责人维护任务板；“待用户review”不等于已批准，“文档完成”不等于产品完成。
- 发布：先完成可review产物和验证，再由用户决定实际发布位置与公开范围。

## 交接要求

每个实现任务启动前提供需求ID、场景/步骤ID、内容与数据样例、验收条件、来源状态。交付时附文件、验证证据、限制及遗留事项。

内容作者 → 专业交叉复核 → 交互与架构对齐 → QA审查 → 用户关键文档review → 范围明确的实现 → 验收 → 发布准备。

不需要用户逐项批准文字修订或普通代码选择；涉及学习范围、核心路线或公开发布的重大变化需呈现具体变更供review。
