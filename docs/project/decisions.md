# 决策记录

## ADR-001：第一版使用静态模拟

状态：用户已确认。

目的：让读者先理解全过程，无需 API 密钥、真实酒店账户或 GPU。

决策：中文静态交互网站，演示数据明确标记为模拟；真实模型、酒店和支付接入另立迭代。

影响：可以确定性重放、后退与复位。数字不得作为实测性能或真实交易结果。

## ADR-002：双层阅读

状态：用户已确认目标读者；分层方式为团队设计。

决策：同一场景默认直观叙述，可展开工程细节；不拆成两套相互脱节的课程。

验证：此处早期读者范围已被ADR-005替代；实现后邀请偏业务沟通和偏技术方案的目标读者试读。尚未执行。

## ADR-003：前端技术与共享进度

状态：设计建议，待实现前确认与验证。

决策建议：原生 HTML/CSS/JavaScript ES modules，无运行时远程依赖。一个确定性场景状态驱动四个视角，资源数值是步骤快照。

原因：降低静态部署与维护成本，避免框架选择先于内容设计；切换视角不改变进度。

限制：目前没有运行页面；浏览器兼容和无障碍要求将在实现阶段验证。

## ADR-004：术语与性能边界

状态：文档阶段统一约束。

决策：QKV 与 KV Cache 分开说明；服务器/节点与 Kubernetes Pod 分开；显存估算与性能压测分开。RDMA、RoCE、InfiniBand、NVLink 不互作同义词。

来源：专业文档候选链接尚需逐条核验；框架和硬件相关结论注明适用范围。

## ADR-005：目标读者聚焦思科生态

状态：用户明确指定，取代ADR-002中早期宽泛目标读者。

读者为思科客户、合作伙伴、销售与售前工程师，有网络和IT背景，无大模型和AI背景。保留分层阅读，层名为理解与沟通/方案与工程细节。按业务→模型→GPU→网络→UCS方案组织，所有内容及试读遵循docs/product/audience.md。静态模拟范围不变。

## ADR-007：大需求先做预研

状态：用户明确授权。

较大或不确定的需求先出需求/功能预研文档，列来源、候选方案、复杂度、风险和分期，再与用户讨论内容取舍。已明确的REQ保持，预研只细化或提出具体变更；灵感无需可行性评估且不自动入排期。预研候选选择后同步全部管理文档。
