# 目标读者与教学表达规范

状态：用户明确指定，替代早期“完全非技术读者与软件工程师入门”的宽泛定位。适用于全部需求、内容、设计和验收文档。

## 核心读者

思科客户、合作伙伴、思科销售、思科售前工程师。他们普遍具备网络与IT背景，但没有大模型与AI背景。用户进一步明确：他们的日常工作主要是网络维护、虚拟化维护和云平台维护。

不按职位推定所有人技术深度相同。共享基础学习路线，按需展开方案与工程细节；不要求编程、机器学习或GPU经验。

| 读者 | 最关心的问题 | 学完应能做什么 |
| --- | --- | --- |
| 客户 | AI能解决什么业务问题？为什么需要这些基础设施？ | 说明业务流程、体验目标与容量需求，提出部署问题 |
| 合作伙伴 | 如何把模型、服务器、网络和应用组成可交付方案？ | 梳理组件职责、依赖、兼容证据及验证计划 |
| 销售 | 如何解释价值和配置差异，避免只报GPU型号？ | 用响应速度、并发、上下文与成本讲清选择；识别需售前确认的问题 |
| 售前工程师 | 如何收集工作负载、估算容量、设计通信与验证方案？ | 区分显存容纳和性能达标，解释拓扑、资源共享与压测口径 |

## 已知与未知

可借用服务器、链路、带宽、延迟、吞吐、队列、拥塞、冗余和服务目标等熟悉概念，但仍提供简短定义与单位，不用缩写堆砌。

必须从零解释token、prefill/decode、QKV/KV cache、模型参数与维度、Dense/MoE、embedding/reranker/RAG、GPU计算与互联。不要假设网络工程经验自然包含RDMA/RoCE或AI集群配置经验。

## 从日常运维经验建立理解

| 熟悉的工作 | 对应的AI学习问题 | 类比边界 |
| --- | --- | --- |
| 网络维护：链路、拥塞、延迟、丢包及故障定位 | 请求在哪一层等待？GPU机内和跨机通信为何拖慢推理？ | NIC带宽不等于GPU显存带宽；NVLink不是以太网；不是所有慢请求都因网络 |
| 虚拟化维护：资源分配、超配、隔离与邻居争用 | 多模型如何分GPU？显存够不够？共享后能否保持稳定？ | GPU显存不像普通VM内存可默认超配；MIG、时间共享与vGPU是不同机制，需分别核验支持 |
| 云维护：副本、调度、扩缩容、配额与可用性 | 模型副本和分片有何区别？高峰如何排队、限流和扩容？ | GPU模型加载及缓存影响启动和调度；多副本不等于模型并行 |
| 运维监控：利用率、告警、SLO与容量预测 | 看哪些指标判断模型服务健康？GPU忙为何用户仍觉得慢？ | GPU利用率不能单独证明吞吐或体验达标；区分TTFT、ITL、尾延迟和工具等待 |

示例应包含：同一模型突然变慢时逐层定位、多用户高峰容量规划、多模型资源争用、知识库更新与查询、节点故障下的服务恢复。仍先用酒店场景串起整体，再用这些熟悉的生产问题深入。

不要因读者有IT经验就跳过token、模型权重、prefill/decode和KV Cache，也不要把AI系统画成普通虚拟机换了一个名称。运维背景是解释桥梁，不代表所有销售人员亲自操作全部系统；按需提供基础入口。

## 教学主线

业务请求 → Agent与工具 → 模型调用 → GPU上的计算和缓存 → 多用户服务 → 单机/跨机通信 → UCS配置与容量 → 方案验证与体验。

酒店场景用于把业务、应用和基础设施连接起来；随后引入企业知识库案例。先解释“发生什么、为何需要这个组件、对体验有什么影响”，再展示术语、公式和配置。

两层阅读入口改为：

- **理解与沟通**：业务流程、组件职责、直观指标和配置价值，所有角色均可阅读。
- **方案与工程细节**：模型配置、每卡账本、网络拓扑、GPU支持证据与测试方法，客户技术人员、伙伴及售前可展开。

角色入口是推荐路线，不限制读者访问内容；四个运行视角user/agent/model/infra仍是同一流程的观察方式，不等于四种职业角色。

## 思科场景与表达边界

以Cisco UCS及相关网络部署问题为重点，对具体支持关系使用官方证据。解释通用AI机制时不将厂商产品当成唯一实现方式。资料帮助理解和方案沟通，不替代配置工具、正式兼容矩阵或性能验证，不用未经核验的营销倍率推导用户体验。

每个参数的说明至少回答：含义是什么、方案设计为何关心、升高/降低可能改变什么、客户感受到什么、什么条件下不成立。

## 验收调整

- 理解与沟通路线：读者能解释模型与工具的职责、首token与持续输出的区别、GPU/网络配置为何影响体验。
- 方案路线：读者能收集模型、长度分布、到达率、并发、延迟目标等输入，并说明容量估算与压测如何配合。
- 验证覆盖客户/伙伴和销售/售前场景；至少邀请一位偏业务沟通、一位偏技术方案的目标读者试读，不以AI专业人员代替。
- 仍检查术语是否首次解释、网络类比是否准确、基础路线是否无需代码或公式即可完成。

当前尚未进行目标读者试读；以上为后续验收标准。
