状态：待 review；M0 文档设计，不表示页面已实现。读者、范围和阶段以[需求](../product/requirements.md)、[读者规范](../product/audience.md)和[任务板](../project/tasks.md)为准。技术契约见[整体架构](architecture.md)。

## 1. 读者与两条路线

面向 Cisco 生态客户、合作伙伴、销售与售前，日常从事网络、虚拟化或云平台维护，没有 AI 背景。职业角色入口用于选择学习目标，不对应系统运行角色。使用熟悉的请求路径、排队、容量、隔离和故障定位解释 AI；类比之后明确边界，例如 GPU 显存不能简单等同虚拟机内存分配。

- **理解与沟通路线**：酒店八步 → 基础推理与等待 → RAG → 单卡/多卡/多机总览 → GPU/UCS 参数的用户体验含义。目标是能解释责任、等待与方案取舍。
- **方案与工程细节路线**：酒店八步 → 模型配置/张量形状 → prefill/decode/QKV/KV → 容量和并发 → 机内/跨机网络 → 多模型调度 → GPU/UCS 配置核验。目标是提出合理容量、网络与运维问题。

两条路线共享页面和场景，只改变推荐顺序与默认展开深度；不要求读者编程。每页先回答一个具体问题，再给可点击过程，最后提供工程细节、来源和自测。

## 3. 酒店统一八步与四视角

统一步骤：1 接收意图 → 2 整理约束 → 3 应用检查 → 4 查库存与价格 → 5 比较候选 → 6 用户确认 → 7 应用执行预订 → 8 告知结果。细节与异常依据[推理内容规格](../content/inference.md)。缺失字段在应用检查进入澄清分支；补充后重新检查。库存不足、超时和价格变化提供明确分支，价格变化需重新确认；状态未知不得自动展示成功。

四视角固定为用户（user）、智能体（agent）、模型（model）、基础设施（infra）。切换保持请求、步骤和分支。模型提出工具调用，智能体程序检查并执行；工具等待时模型可无新动作，基础设施可服务其他请求。不能为了四视角都有动画而虚构计算。第八步只有模拟工具的成功记录才能显示“模拟预订完成”。

## 4. 页面线框与操作规则

```text
页头：学习地图 / 术语 / 当前路线
目标：一句话 + 学习结束应能回答的问题
场景输入：城市、入住/退房日期、人数、预算；模拟标记
视角：[用户] [智能体] [模型] [基础设施]
八步导航：当前步骤名称、第 N / 8 步
主区域：流程图 + 对应有序文本
说明：谁 / 输入 / 动作 / 输出 / 等待什么
状态：工具、队列、GPU 活动、显存/KV、延迟阶段（示意）
控制：上一步 / 下一步 / 重置 / 自动播放（默认关闭）
展开：为什么 / 从运维看 / 工程细节 / 假设与来源
自测：解释责任、资源与故障位置
```

点击步骤、前进后退均读取确定性快照，重复点击不累加资源。重置回到初始步骤并关闭播放；切换视角保留进度与暂停状态。手动跳步和标签页进入后台暂停播放；开启后每步至少停留 4 秒。用户确认节点自动暂停，必须明确选择确认才能走成功分支；教学跳步只能显示未确认状态，不能绕过确认生成成功结果。

分支使用明显的选择按钮和路径标签。返回分支选择点允许重新选择；不要残留其他分支的确认或订单状态。输入输出默认显示简短字段卡，JSON 在工程细节展开。资源数字带单位与假设；未建模显示“本演示未估算”，不能显示为零。

图例统一：用户输入、模型计算、程序/工具、等待、完成；箭头标记请求、结果、数据或通信。颜色配合图标/文字/线型。运维入口串起客户端、应用/工具、队列、GPU/缓存、机内与跨机链路；不以单一 GPU 利用率判断健康。

## 5. 响应式与无障碍

宽屏流程与解释并排；移动端依序展示步骤、纵向流程、解释和状态，避免缩小整幅机架图。拓扑采用逐层展开，保留通信路径文本。320 CSS 像素及 200% 缩放下主要内容无需横向滚动，宽参数表允许独立滚动并保留行标题。

原生按钮和展开控件优先；焦点可见，Tab 可达全部操作，Enter/Space 可激活，无键盘陷阱。标签页支持方向键和正确面板关联，无法正确实现则使用普通按钮组。当前步骤有可访问名称与状态；更新仅简短礼貌播报，不反复播报计数器。图有等价有序文本，提示可点击和聚焦，不依赖悬停。点击目标至少 44 × 44 CSS 像素，正文对比至少 4.5:1。

尊重 prefers-reduced-motion，关闭移动箭头、粒子与位移过渡；静态高亮仍表达完整状态。动画不是必需教学信息，自动播放保持主动开启。

## 6. 交接与验收

内容负责人提供八步四视角、分支、术语、快照假设和来源状态；Infra 核对单位、资源与通信；产品核对读者与确认边界；前端按架构契约实现；QA 保存实际测试证据。当前文档只能通过一致性评审，不能标为功能测试通过。

M1 验收：静态 HTTP 可运行、无密钥；八步与四视角同步；完整成功/澄清/失败路径；确认不能绕过；回退重置确定性；模拟标识持续可见；键盘、窄屏和减少动效可用。邀请理解沟通路线与方案工程路线各至少一名目标读者，能复述谁执行工具、首次等待原因、GPU 等待与工具等待的区别。

M2 验收增加 RAG 数据衔接、公式单位与边界、未核验配置标识、吞吐/延迟估算边界；M3 增加通信数据与拓扑、多模型隔离、Pod 语义。阶段证据归入[质量规范](../quality/validation.md)。
