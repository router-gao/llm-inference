# 首页体验设计 v0.1：先玩一个场景，再理解AI

状态：待用户review的设计；尚未实现页面。用户明确首页必须初学者友好、非学术、非技术手册、寓教于乐；兼顾对技术兴趣不高的销售和非IT读者。既有网络/IT读者仍是核心，新增访客不被技术前置门槛挡住。

## 首页目标

访客不用懂GPU、模型或网络术语，也能开始一个场景；先看到业务结果与参与者，再决定是否深入。首页传达“你能亲手看懂一件事”，不要求先阅读整套课程。

## 页面结构与文案建议

1. **首屏：一个可互动的小故事。** 标题候选：“一句话，AI究竟做了多少事？”说明：“点几下，看懂AI订酒店、回答问题和制作视频的过程。”主按钮“帮我订个酒店”，次按钮“让一句话变成视频”。持续显示教学模拟标签。示意图优先人物、场景与状态，避免首屏机架拓扑和参数表。
2. **立刻发生一件事。** 在首页显示故事预览与一个明确可点击动作，如选择日期→观察助手询问→出现候选；进入完整旅程时保留上下文。预览不伪称真实交易/生成，跳步不绕过确认。
3. **三个场景入口。** “AI替我办事”（Agent）、“AI帮我找答案”（RAG）、“AI把想法变成视频”（视频）。英文名按需展开；未交付场景标“即将开放”，不得用空按钮假装可用。
4. **一个轻量挑战。** “AI说‘订好了’，就真的有订单了吗？”点击选择后用解释反馈，不羞辱错误、不设必须通关门槛、不需要登录。其他例题围绕“为什么等第一句话”和“多人一起用会怎样”。
5. **按兴趣继续。** “我想讲清AI能做什么”“我想看懂为什么会慢”“我想设计GPU与网络方案”。不是按职位锁定内容，不暗示非IT读者能力不足。
6. **今天学一点。** 展示可独立完成的小单元与学习目标，估计阅读时间仅在试读后校准；避免未经验证的精确分钟承诺。完整课程/术语/来源放在次级导航，随时可查。

## 娱乐性与学习真实性

轻量人物对话、卡片变化、猜测/揭晓、请求接力与资源可视化用来支撑一个解释。可以有温和动效，但关键信息不依赖动画；尊重减少动效和键盘操作。不给“AI魔法”式无边界暗示，也不以积分、排行榜或强制闯关增加负担。

“技术兴趣低”不等于“阅读能力低”。用具体业务收益、可观察后果和短解释，不堆缩写；高级内容可展开，专业读者仍可快捷进入配置/网络章节。可提供“先看结果 / 看过程 / 工程细节”层次，但结果必须注明模拟或预生成。

## 首屏避免

论文摘要、产品白皮书布局、目录墙、公式、代码、GPU型号大表、全量英文缩写、密集网络拓扑，以及未解释的prefill/QKV/RDMA。无需技术术语才能理解主按钮，来源与工程细节不隐藏但不压过故事。

## 排期与验收

M1交付首页、可玩的酒店入口、兴趣路线和一个小挑战。RAG卡在M2交付，视频卡仅可链接独立项目Omni Canvas，不绑定主站M2交付；提前出现需清楚标为待开放。M3新增方案/运维入口，不能让后续功能增加首页复杂度。

试读包含偏业务沟通、网络/云维护及缺少IT背景的访客。检查是否无需术语解释就找到入口、完成第一个动作、愿意继续，并能复述关键责任与模拟边界；记录疑惑和兴趣反馈，不把“点击了”当“理解了”。无障碍、窄屏与减少动效检查仍适用。当前尚未试读，不声称吸引力已验证。

## 用户review重点

首屏故事是否有吸引力；三个场景是否贴近读者；挑战语气是否友好；是否让对技术不感兴趣的人有进入理由；工程入口是否仍便捷。具体视觉方案需后续原型review，本稿不是已完成视觉效果。
