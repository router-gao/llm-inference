# 需求与功能预研入口

用户授权：对较大或不明确的需求，可以先做需求/功能预研，输出文档供讨论，再确定交付范围。记录要求不等于批准技术方案；不能以预研为由遗漏已提出的主题。

## 什么时候先预研

跨多个模块、需要较多外部事实或产品支持核验、存在不同方案/实现复杂度、会明显改变范围或排期时，先预研。简单且范围明确的修订直接同步需求与任务，不增加无必要流程。

## 一份预研至少回答什么

1. 用户原始要求、读者问题和关联需求；明确已确认、假设与待讨论内容。
2. 希望带来的学习成果与典型使用场景。
3. 实际读取的资料、支持哪些结论、版本/日期及未核验事项。
4. 候选功能/内容和替代方案，说明收益、复杂度、依赖与风险。
5. 推荐范围、分期建议、验收方式；未知工作量标待估，不编造日期。
6. 已完成的检查、具体阻塞、仍需用户讨论的关键选择。
7. 决定后怎样更新PRD、课程、设计、任务与排期，保留可追踪编号。

预研可讨论实现可行性，但不能将未做的实验、产品测试或兼容核验写为通过。外部事实受阻时完成独立工作，列明精准依赖。

## 状态与转化

待预研→预研中→待讨论→已选入/暂缓/不选入。暂缓或不选入须记录理由与用户意见；无回复不算认可。入选后关联稳定REQ及任务，并说明验收/阶段。研究候选不自动成为开发承诺。

[灵感随手记](../project/ideas.md)不在此列表中自动转化；只有用户明确要求推进或将想法转为要求后，才进入需求/预研记录。
